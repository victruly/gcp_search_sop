SOP STEP 01 雲端基礎環境

申請與建立 GCP 專案 (Project & Billing)

🎯 作業目標：建立專案命名空間、關聯計費帳戶並設定安全預算警示
#01
📝 控制台操作步驟 (Console Operations)
  • 1
    登入 Google Cloud 控制台
    瀏覽器前往 console.cloud.google.com，使用企業管理員或技術負責人帳號登入。
  • 2
    建立新專案 (New Project)
    點擊頂端選單列的「專案下拉選單」➔ 點選右上角的「新增專案 (New Project)」按鈕。
  • 3
    設定專案名稱並取得 Project ID
    輸入專案名稱 (如 gcp-agent-search)，系統將自動產生全域唯一的 Project ID (如 gen-lang-client-0687915907)，請務必記錄保存。
  • 4
    關聯計費帳戶 (Billing Account)
    前往「帳單 (Billing)」專區，將專案關聯至公司合約計費帳戶或啟用 $300 美金免費試用額度。
  • 5
    設定預算警報 (Budget Alerts)
    在帳單後台建立預算警戒門檻 (例如達 50%、80%、100% 時即時寄發 Email 給主管)。
🔑 關鍵配置參數 (Parameters)
  • 專案名稱 (Project Name)： gcp-agent-search
  • 專案 ID (Project ID)： gen-lang-client-0687915907
  • 預設計費帳戶： Enterprise Billing Account (已綁定)
⚠️ 主管與資安審核重點
1. 計費綁定為必要前提：若未綁定計費帳戶，後續 Discovery Engine API 將無法啟用。
2. Project ID 建立後不可更改：後續所有 Python 後端配置與 IAM 金鑰均綁定此 ID。
3. 預算預警防線：透過 Budget Alerts 確保每筆開銷在受控範圍內。
✓
SOP 階段檢核點：取得有效且已啟用計費的專案 ID (Project ID)，可在控制台頂端順利切換至該專案。
SOP STEP 02 雲端基礎環境

啟用 Vertex AI Search (Discovery Engine API)

🎯 作業目標：啟動 Google 核心語意搜尋服務引擎 (Discovery Engine API)
#02
📝 控制台操作步驟 (Console Operations)
  • 1
    搜尋並進入 Agent Builder 儀表板
    在 GCP 控制台頂端搜尋欄輸入「Agent Builder」或「Vertex AI Search」並按下 Enter。
  • 2
    首次進入服務啟用導航
    專案首次進入時將出現歡迎與功能說明視窗，點擊「繼續並啟用 API (Continue and activate the API)」按鈕。
  • 3
    背景自動配置 API 資源
    系統會自動為專案啟用 discoveryengine.googleapis.com 服務，此過程約需 1~2 分鐘。
  • 4
    驗證 API 啟用狀態
    前往「API 和服務」➔「已啟用的 API 和服務」，確認清單中包含 Discovery Engine API 且狀態為綠色正常。
🔑 API 規格與服務端點
  • 服務名稱： Discovery Engine API
  • API Identifier： discoveryengine.googleapis.com
  • 預設區域 (Location)： global (全球分散式，提供最佳檢索性能)
⚠️ 常見障礙排除與權限要求
1. 操作人員權限：操作者須具備專案 Owner 或 Service Usage Admin 權限才能啟用 API。
2. 傳播時間差：API 剛啟用後 2 分鐘內若後端呼叫出現 403/404，屬 IAM 規則同步之正常現象，稍後即可恢復。
✓
SOP 階段檢核點：Discovery Engine API 顯示為啟用中，Console 能順暢進入 Agent Builder 儀表板。
SOP STEP 03 搜尋引擎實體

建立 Search 應用程式 (App / Engine)

🎯 作業目標：配置搜尋引擎執行個體、自訂功能特性並生成專屬 Engine ID
#03
📝 控制台操作步驟 (Console Operations)
  • 1
    進入 Apps 應用程式專區
    在 Agent Builder 左側功能導覽列中，點擊「應用程式 (Apps)」進入管理列表。
  • 2
    點選建立新應用程式
    點擊頂端「＋ 建立應用程式 (Create App)」按鈕啟動配置精靈。
  • 3
    選擇應用程式類型：搜尋 (Search)
    在四大應用程式類型 (Search / Chat / Recommendation / Agent) 中，選取「搜尋 (Search)」。
  • 4
    勾選進階與 AI 生成答案特色
    勾選「企業版功能 (Enterprise Edition)」並啟用「Generative Answers (AI 答案總結)」以獲得最佳語意萃取效果。
  • 5
    命名並取得 Engine ID
    命名應用程式 (如 pbsearch)，系統將生成全域唯一的 Engine ID (如 pbsearch_1791792965002)。
🔑 應用程式實體參數
  • App Type： Search (Generic Search)
  • App 名稱： pbsearch
  • Engine ID (重要)： pbsearch_1791792965002
  • Generative AI 摘要： 已啟用 (含來源引文標註)
💡 關鍵架構決策說明
• Engine 與 Data Store 解耦：一個 Engine 可同時掛載多個 Data Store，日後可無縫擴充內部 PDF 文件。
• 後端必要呼叫路徑：Python SDK 發送 SearchRequest 時必須指定此 Engine ID。
✓
SOP 階段檢核點：成功建立 Search App，記錄專屬 Engine ID 供後續 Python 後端環境變數配置使用。
SOP STEP 04 資料存放區

建立資料存放區 (Data Store) 並配置網站檢索

🎯 作業目標：核心選用「進階網站搜尋 (Advanced)」，免驗證外部網域擁有權
#04
📝 控制台操作步驟 (Console Operations)
  • 1
    進入 Data Store 建立精靈
    在建立 App 流程的「資料 (Data)」步驟，或前往左側「資料存放區」選單，點選「建立資料存放區」。
  • 2
    選取資料來源類型：網站 (Websites)
    在 Cloud Storage、BigQuery、網站等選項中，選取「網站 (Websites)」。
  • 3
    ★ 核心步驟：選取進階網站搜尋 (Advanced)
    在網頁索引模式中，務必選取「進階網站搜尋 (Advanced Website Search)」，切勿選取基礎模式。
  • 4
    命名資料存放區並完成綁定
    輸入資料庫名稱 (如 pbdatastore)，系統生成 Data Store ID (如 pbdatastore_1791793664793)，並連接至 Search App。
⭐ 核心決策：基礎 vs 進階網站搜尋
• 基礎模式 (Basic Website Search)：
強制要求透過 Google Search Console 驗證網域擁有權！只能爬取公司自家持有的單一網域。

• 進階模式 (Advanced Website Search)：
免網域驗證！可自由爬取第三方、產業協會、技術論壇等 50 個外部公開網站。

👉 結論：要納入 50 個各類別網站，必須選取 Advanced！
🔑 資料存放區配置參數
  • 資料庫名稱： pbdatastore
  • Data Store ID： pbdatastore_1791793664793
  • 索引技術： Advanced Website Indexing
✓
SOP 階段檢核點：Data Store 成功建立為 Advanced Website 模式，並與 Search App 完成關聯。
SOP STEP 05 資料庫建置

批量新增 50 個目標網站至搜尋白名單

🎯 作業目標：設定 Included Patterns 網址比對規則、啟動 Googlebot 爬取索引
#05
📝 控制台操作步驟 (Console Operations)
  • 1
    進入 Data Store 網址管理介面
    點選剛剛建立的 Data Store (pbdatastore) ➔ 切換至「資料 (Data)」或「管理」頁籤。
  • 2
    點選「新增比對模式 (Add URL patterns)」
    在 Included Patterns 區域點選新增，介面支援批次貼上多行網址規則。
  • 3
    依標準語法輸入 50 個網址
    每行一個目標網站，使用萬用字元 /* 涵蓋全站內容：
    https://www.semicontaiwan.org/*
    https://tech-portal-example.com/*
    https://industry-docs.org/*
  • 4
    也可透過 Cloud Storage 批次匯入
    若網站清單較多，可將 50 個網址存為 CSV/TXT 文字檔上傳至 Cloud Storage Bucket 一鍵快速匯入。
  • 5
    儲存並啟動 Googlebot 索引排程
    點選儲存後，Google 爬蟲將依序檢索網頁並建立分散式向量檢索庫。
🌐 URL Pattern 比對規則語法
  • 全站收錄模式： https://domain.com/* (包含所有子路徑文章)
  • 精確子目錄收錄： https://domain.com/news/* (僅收錄新聞分類)
  • 排除規則 (Excluded Patterns)： 可設定排除 login、登入頁或無效版權頁
⏱️ 爬蟲排程與索引時間說明
1. 初始索引時間差：新增 50 個網站後，Googlebot 需 2 至 24 小時完成初始爬取與向量建立。
2. robots.txt 規範：若目標網站明確宣告 Disallow Googlebot，則無法被收錄。
3. 自動更新：Google 會自動排程回訪，網站有新文章時自動同步。
✓
SOP 階段檢核點：50 個目標網站正規化 URL Pattern 已完整納入白名單，爬取狀態顯示運作中。
SOP STEP 06 身分與存取控制

建立 IAM 服務帳戶並授權 (Service Account)

🎯 作業目標：建立程式專用連線身分，貫徹最小權限資安原則 (Least Privilege)
#06
📝 控制台操作步驟 (Console Operations)
  • 1
    導航至 IAM 服務帳戶專區
    於主選單前往「IAM 與管理 (IAM & Admin)」➔ 點選「服務帳戶 (Service Accounts)」。
  • 2
    點選建立服務帳戶
    點擊頂端「＋ 建立服務帳戶 (+ CREATE SERVICE ACCOUNT)」開啟配置精靈。
  • 3
    輸入帳戶名稱與描述
    輸入服務帳戶名稱 (如 gcp-search-backend-sa)，系統自動生成對應的 Email。
  • 4
    指派專用 IAM 角色權限 (Grant Access)
    在角色下拉選單中搜尋並選取：
    Discovery Engine Viewer (roles/discoveryengine.viewer)
  • 5
    完成建立並確認權限
    點選「完成 (Done)」，該服務帳戶即刻具備呼叫 GCP 搜尋 API 的合法身分。
🛡️ 核心 IAM 角色權限對照表
  • Discovery Engine Viewer (推薦)： 唯讀檢索 (search) 權限，符合生產環境最小權限
  • Discovery Engine Admin： 完整讀寫、新增刪除 Data Store 權限
  • 服務帳戶 Email 範例： sa-backend@gen-lang-client-xxxx.iam.gserviceaccount.com
🔒 長官資安把關重點
1. 嚴禁授予 Project Owner/Editor 角色：防止金鑰外洩時整個專案遭到竄改。
2. 精準鎖定 Discovery Engine Viewer：落實權限最小化 (Least Privilege)。
3. Cloud Audit Logs：所有透過此身分發出的搜尋請求均留存於 GCP 稽核日誌。
✓
SOP 階段檢核點：服務帳戶建立完成，並已成功繫結 Discovery Engine Viewer 角色。

SOP STEP 09 程式碼實作

Python 後端程式撰寫：憑證載入與呼叫 Search

🎯 作業目標：利用私鑰完成 OAuth2 驗證、發送 SearchRequest 並結構化解析回傳
#09
💻 核心後端呼叫邏輯 (Python SDK 範例)
app.py 
import os
from google.oauth2 import service_account
from google.cloud import discoveryengine_v1 as discoveryengine

# 1. 載入私鑰 JSON 憑證
credentials = service_account.Credentials.from_service_account_file(
    os.getenv("GCP_KEY_FILE"),
    scopes=["https://www.googleapis.com/auth/cloud-platform"]
)

# 2. 初始化搜尋客戶端
client = discoveryengine.SearchServiceClient(credentials=credentials)

# 3. 組合搜尋 Serving Config 資源路徑
serving_config = (
    f"projects/{os.getenv('GCP_PROJECT_ID')}/locations/{os.getenv('GCP_LOCATION')}/"
    f"collections/default_collection/engines/{os.getenv('GCP_ENGINE_ID')}/servingConfigs/default_search"
)

# 4. 發起搜尋請求 (含 AI 摘要配置)
request = discoveryengine.SearchRequest(
    serving_config=serving_config,
    query="半導體測試",
    page_size=10,
    content_search_spec=discoveryengine.SearchRequest.ContentSearchSpec(
        summary_spec=discoveryengine.SearchRequest.ContentSearchSpec.SummarySpec(
            summary_result_count=5,
            include_citations=True
        )
    )
)

# 5. 取得回應結果
response = client.search(request=request)
🔍 核心邏輯架構解析
  • 1. 認證授權 (OAuth2)： SDK 自動在背景進行 JWT 簽章換取短期 Token

🎨 前端整合支援兩種模式 (Dual Integration Modes)
  • 1
    模式一：自訂 UI 搜尋介面 (推薦，自由度最高)
    • 架構：前端以純 HTML/JS 發送 AJAX POST /api/search 至 Python 後端。
    • 特色：自訂流光暗色或明亮風格，卡片式呈現標題、連結、摘要與 AI 答案總結。

  • 2
    模式二：Google 官方現成小工具 (<gen-search-widget>)
    • 架構：前端引入 Google 官方 Web Component 小工具標籤。
    • 特色：開箱即用，自帶自動補全、分頁導航與精美排版。
    • 資安：由 Python 後端 /api/token 動態派發短期 OAuth Access Token 給前端賦值。

🔒 資安防護與金鑰維運
• 金鑰定期輪替 (Key Rotation)

建議每 90 天於 GCP 控制台生成新金鑰並平滑替換舊金鑰，確保憑證時效安全。

• Secret Manager 整合

進入生產環境時，建議將金鑰存入 Google Secret Manager，避免伺服器實體檔案儲存。

• 網路與流量防護

後端 API 可掛載 Cloud Armor WAF 或設定來源 IP 白名單阻擋惡意爬取。

💰 成本分析與配額優化
• 計價機制透明

Vertex AI Search 採搜尋次數 (Queries) 計價，每月提供 1,000 次免費呼叫額度。

• 快取機制 (Caching)

後端可針對熱門關鍵字建立 Redis 快取 (TTL 1 小時)，大幅降低 60% 重複 API 費用。

• 專案配額上限防護

設定 Quotas 上限，防止非預期暴增的查詢花費。

本 Python 後端 API 可直接封裝為 Slack、Microsoft Teams 或 LINE 企業機器人。
